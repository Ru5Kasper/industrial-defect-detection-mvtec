# План работы: Башмаков

## Роль

Собрать сопоставимый baseline на PaDiM, организовать общую оценку моделей, провести анализ ошибок и подготовить интегрированные материалы для итогового отчёта.

## Результат работы

К моменту сдачи в репозитории должны быть:

- воспроизводимый запуск PaDiM на MVTec AD;
- единая таблица метрик PatchCore и PaDiM;
- сохранённые качественные примеры и разбор ошибок;
- готовые разделы отчёта о методах, экспериментах, метриках и выводах;
- README с проверенной инструкцией запуска.

## Этап 1. Подготовить общий интерфейс эксперимента

1. Согласовать с командой единые категории пилота: `bottle`, `cable`, `carpet`.
2. Зафиксировать единые параметры сравнения: seed `42`, размер изображения `256`, стандартное разбиение MVTec AD.
3. Определить единый формат результатов:
   - `results/metrics.csv` — одна строка на модель и категорию;
   - `results/figures/<model>/<category>/` — изображения, heatmap и маски;
   - `configs/<model>.yaml` — все параметры запуска.
4. Не менять формат данных и метрик без согласования с авторами соответствующих модулей.

## Этап 2. Реализовать PaDiM-baseline

1. Добавить `configs/padim.yaml` с seed, путём к данным, категориями и размером изображения.
2. Реализовать запуск PaDiM в `src/train.py` или в отдельном `src/train_padim.py`.
3. Обучать только на `train/good`.
4. Реализовать `src/infer.py` или `src/infer_padim.py`, который сохраняет:
   - score аномальности изображения;
   - карту аномалий;
   - бинарную предсказанную маску;
   - итоговую визуализацию: исходное изображение, ground truth, heatmap, prediction.
5. Проверить один полный запуск на `bottle` до расширения на остальные категории.

## Этап 3. Оценка и сравнение

1. Рассчитать для PaDiM `image_auroc`, `pixel_auroc`, `aupro` и время инференса.
2. Записать результаты в `results/metrics.csv`; не перезаписывать строки PatchCore.
3. Сравнить PaDiM и PatchCore на одинаковых категориях и разбиениях.
4. Построить итоговую таблицу со строками по категориям и средней строкой `mean`.
5. Подготовить один график сравнения методов по основным метрикам.

## Этап 4. Анализ ошибок

Для каждой модели выбрать и сохранить минимум по одному примеру:

- true positive — дефект найден и локализован;
- true negative — исправный объект корректно определён как нормальный;
- false positive — нормальный объект ошибочно признан дефектным;
- false negative — дефект пропущен или локализован плохо.

Для каждого неудачного примера указать вероятную причину: малый размер дефекта, слабый контраст, блики, сложная текстура, нетипичный ракурс или недостаточная репрезентативность нормальных изображений.

## Этап 5. Отчёт и финальная интеграция

1. Подготовить черновики разделов:
   - «Выбранные методы»;
   - «Ход экспериментов»;
   - «Полученные метрики и примеры работы»;
   - «Анализ ошибок и выводы»;
   - «Вклад участников».
2. Обновить README точными командами запуска после проверки в чистом окружении.
3. Проверить, что в Git не добавлены датасет, веса или другие большие файлы.
4. Оформить pull request из `bashmakov` в `main` после завершения каждого содержательного этапа.
