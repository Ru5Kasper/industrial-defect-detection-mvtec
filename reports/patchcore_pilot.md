# PatchCore — пилотный эксперимент

> **Статус:** обучение и оценка успешно выполнены на реальном датасете MVTec AD для категорий bottle, cable и carpet. Получены метрики, сохранены модели и примеры визуализаций.

## 1. Метод

Реализована собственная прозрачная версия PatchCore.

Замороженный ImageNet ResNet-18 извлекает признаки из слоёв layer2 и layer3. Карта признаков layer3 интерполируется до пространственного размера layer2; признаки конкатенируются и проходят локальную агрегацию average pooling 3×3.

Все патчи из нормальных обучающих изображений train/good формируют набор кандидатов для memory bank. Алгоритм greedy k-center coreset уменьшает его до заданной доли. Для каждого тестового патча находится ближайший нормальный дескриптор. Расстояния формируют anomaly map, а максимальное значение карты используется как image score.

## 2. Протокол эксперимента

- Датасет: MVTec AD.
- Пилотные категории: bottle, cable, carpet.
- Входные изображения: RGB, 256×256.
- Нормализация: ImageNet mean/std.
- Seed: 42.
- Устройство: CPU.
- Обучение использует только изображения train/good.
- Для итоговой оценки используются официальные test и ground_truth.
- Порог бинарного решения калибруется как 99,5-й процентиль image scores на train/good.
- Image AUROC рассчитывается по оценкам изображений.
- Pixel AUROC и AUPRO рассчитываются по картам аномалий и маскам дефектов.
- AUPRO рассчитывается приближённо по 300 порогам при максимальном FPR=0.30. Это дискретное приближение, а не интегрирование по всем уникальным значениям score.

## 3. Фактическая конфигурация

Для завершённого эксперимента использовались следующие параметры:

| Параметр | Значение |
|---|---|
| Backbone | ResNet-18, ImageNet1K_V1 |
| Извлекаемые слои | layer2 и layer3 |
| Размер изображения | 256×256 |
| Coreset ratio | 0.001 |
| Максимальный размер memory bank | 5000 |
| Размер блока для поиска ближайших соседей | 2048 |
| Batch size при обучении | 2 |
| Batch size при оценке | 1 |
| Seed | 42 |
| Устройство | CPU |

Обучение и построение memory bank завершились успешно:

| Категория | Изображений train/good | Векторов в memory bank |
|---|---:|---:|
| bottle | 209 | 214 |
| cable | 224 | 229 |
| carpet | 280 | 287 |
| **Всего** | **713** | **730** |

## 4. Результаты

| Категория | Image AUROC | Pixel AUROC | AUPRO | Время, мс/изображение |
|---|---:|---:|---:|---:|
| bottle | 1.0000 | 0.9774 | 0.9294 | 40.38 |
| cable | 0.9196 | 0.9138 | 0.7890 | 43.02 |
| carpet | 0.9723 | 0.9827 | 0.9268 | 42.36 |
| **Макро-среднее** | **0.9640** | **0.9580** | **0.8817** | **41.92** |

Макро-среднее рассчитано как среднее арифметическое показателей трёх категорий.

### Наблюдения

- Для bottle получено Image AUROC 1.0000 — на этой выборке image-level оценки полностью разделили нормальные и дефектные изображения.
- Для carpet получен наилучший Pixel AUROC — 0.9827.
- Категория cable оказалась наиболее сложной: Image AUROC составил 0.9196, AUPRO — 0.7890.
- Среднее время инференса составило около 41.92 мс на изображение на CPU.

Время измеряется в рамках вызова предсказания модели; оно не включает загрузку изображения и построение визуализаций.

## 6. Ограничения и дальнейшие проверки

Эксперимент является пилотным и охватывает только три категории MVTec AD. Результаты не следует автоматически переносить на остальные категории датасета.

Для дальнейшей проверки необходимо:

1. Визуально изучить карты аномалий и убедиться, что они локализуют реальные дефекты.
2. Проверить повторную загрузку сохранённых моделей и воспроизводимость предсказаний.
3. Подробно изучить ошибки модели на категории cable.
4. При необходимости провести дополнительные эксперименты с параметрами coreset.
5. Для строгого сравнения с PaDiM использовать одинаковые preprocessing и проверенный оценщик метрик.

AUPRO в данном эксперименте является приближённой оценкой с 300 порогами и ограничением FPR=0.30.
